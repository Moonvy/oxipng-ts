# `-o 0–6` 的体积与速度，以及参数取舍

测量日期：2026-10-11。Apple M3 Pro，Node v26.7.0，Rust oxipng 10.2.1。

本报告记录修改默认筛选预算之前的四图结果。后续默认 `-o 2` 优化见 [DEFAULT-O2.md](DEFAULT-O2.md)；当前样本目录新增了三张图片，复跑时的数据量和参数已不同。

## 测量方法

使用 `benchmark/sample` 的四张原图，每张、每档、每种实现测量三次，零预热，每次启动独立 CLI 进程。下表耗时是各文件最快值之和，包含进程启动；原始数据也记录每次耗时及中位数。Rust 使用默认线程数，Node 使用单线程内置编码器。

每次输出均在计时结束后独立解码，与输入逐像素比较，并检查重复运行输出的 SHA-256 一致。调参 API 实验也检查完整 16 位像素及 APNG 帧和帧控制信息。API 与 CLI 耗时分别报告，不混算。

这四张图片主要是截图，不能代表照片、索引色、16 位或 APNG 的完整性能分布。

## CLI：全部预设

体积是四张输出文件的字节总和；差距以同一档 Rust 为基准。

| 档位 | Rust 体积 B | Node 体积 B | Node 体积差距 | Rust 耗时 s | Node 耗时 s |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0 | 2,845,750 | 2,799,408 | −1.63% | 0.141 | 1.284 |
| 1 | 2,505,982 | 2,526,183 | +0.81% | 1.702 | 4.524 |
| 2 | 2,473,423 | 2,501,187 | +1.12% | 2.786 | 5.638 |
| 3 | 2,458,357 | 2,485,522 | +1.11% | 3.622 | 8.537 |
| 4 | 2,452,721 | 2,467,196 | +0.59% | 4.956 | 11.299 |
| 5 | 2,450,270 | 2,465,427 | +0.62% | 5.257 | 36.948 |
| 6 | 2,445,742 | 2,460,653 | +0.61% | 8.201 | 66.128 |

Node 从 `-o 2` 升到 `-o 4`，体积降低 1.36%，耗时约翻倍。`-o 5` 比 `-o 4` 仅少 1,769 B（0.072%），耗时达到 3.27 倍；`-o 6` 比 `-o 4` 少 6,543 B（0.265%），耗时达到 5.85 倍。对这组截图，5、6 档的额外搜索收益很小。

`-o 6` 并不保证每张图片都比 `-o 5` 小：`IMG_5112.PNG` 多 91 B，`Image Capture.png` 多 261 B。预设除了增加滤镜，还将 Brute 的评分压缩等级从 1 改成 5，搜索集合并非严格包含上一档的全部候选。

## 预设中的工作量

| 档位 | 最终压缩等级 `--zc` | 滤镜数量 | Brute（行数，评分等级） | 快速筛选 |
| --- | ---: | ---: | --- | --- |
| 0 | 5 | 2 | 无 | 开 |
| 1 | 10 | 2 | 无 | 开 |
| 2 | 11 | 4 | 无 | 开 |
| 3 | 11 | 6 | (3, 1) | 开 |
| 4 | 12 | 6 | (4, 1) | 开 |
| 5 | 12 | 6 | (8, 1) | 关 |
| 6 | 12 | 10 | (8, 5) | 关 |

快速筛选先用较低等级评估候选，最终只对胜出的滤镜做高等级压缩；关闭后会对多个候选做高等级压缩。`--zc` 和滤镜数量也参与像素格式 reduction 的搜索强度判断，因此调整参数不只是改变 Deflate 的速度。

## 单图筛选

先在 `Qjiao.png` 筛选 17 组设置（一次预热、一次测量）。它只用于选择复测对象，不能据此声称稳定提速。

- 两个滤镜配合 `--zc 11`：比原 `-o 2` 大 2.36%；`--zc 9` 快很多，但大约多 12%，不满足接近原体积的目标。
- 四个滤镜配合 `--zc 12`：557,504 B，比原 `-o 2` 的 562,538 B 更小。
- `-o 5 --fast` 与 `-o 6 --fast --brute-level 1`：均为 556,199 B，后者更慢。
- 搜索深度降至 32、保留三轮解析：562,971 B，略大 0.077%；将解析减到两轮：566,211 B，大 0.65%。需要跨图复测速度和体积。

本轮全档实验未改动默认预设，也未根据四张截图直接改写默认行为。后续优化单独记录于 [DEFAULT-O2.md](DEFAULT-O2.md)。

## 四图参数复测：同步 API

每个组合一次预热、三次测量，轮换并反转候选顺序。以下是各图中位数之和；以同一次实验的原 `-o 2` 为参照。

| 参数组合 | 总体积 B | API 耗时 s | 体积变化 | 耗时变化 |
| --- | ---: | ---: | ---: | ---: |
| 原 `-o 2` | 2,501,187 | 5.557 | — | — |
| `-o 1 --zc 11` | 2,524,583 | 4.638 | +0.935% | −16.55% |
| `-o 2 --zc 10` | 2,503,423 | 5.606 | +0.089% | +0.87% |
| `-o 2 --zc 12` | 2,482,204 | 7.894 | −0.759% | +42.05% |
| `-o 5 --fast` | 2,465,427 | 13.378 | −1.430% | +140.73% |
| 深度 32，三轮解析 | 2,503,423 | 5.306 | +0.089% | −4.52% |
| 深度 64，两轮解析 | 2,518,262 | 5.116 | +0.683% | −7.94% |

将 `--zc` 直接降至 10 没有得到稳定的速度收益。缩减搜索深度只有约 4.5% 的 API 提速，已接近测量波动；缩减解析轮数的体积代价更大。删减滤镜的约 16.5% 提速则以接近 1% 的总字节增加为代价，且 `Qjiao.png` 单图增大 2.36%。这些组合没有同时优于原 `-o 2` 的体积和速度。

`-o 2 --zc 12` 对这组截图是一个新的中间选择：比 Rust `-o 2` 仅大 8,781 B（0.355%），体积优于 Node 原 `-o 2`，速度代价小于直接升到 `-o 4`。`-o 5 --fast` 在四张图上与原 `-o 5` 不仅字节数相同，输出 SHA-256 也全部相同；这是样本上的结果，并非快速筛选的一般保证。

## 参数组合的 CLI 复测

再次使用独立进程、零预热、三次测量，取各图最快值之和。

| CLI 参数 | 总体积 B | 最快合计 s | 中位数合计 s | 对 Rust `-o 2` 体积差距 |
| --- | ---: | ---: | ---: | ---: |
| `-o 2`（本轮参照） | 2,501,187 | 6.114 | 6.197 | +1.122% |
| `-o 1 --zc 11` | 2,524,583 | 5.048 | 5.212 | +2.068% |
| `-o 2 --zc 12` | 2,482,204 | 8.252 | 8.682 | +0.355% |
| `-o 5 --fast` | 2,465,427 | 13.601 | 14.144 | −0.323% |

单独复测的原 `-o 2` 是 6.114 s，而全档测试为 5.638 s，差约 8.4%，说明几百分点的速度差需要谨慎解读。与全档测试的 Node `-o 4`（11.299 s）相比，`-o 2 --zc 12` 耗时低约 27%，体积增加约 0.61%；与 Node `-o 5`（36.948 s）相比，`-o 5 --fast` 耗时低约 63%，四图输出完全一致。两者是不同实验轮次的比较，原始数据保留了全部测量样本。

在这四张截图上，接近 Rust `-o 2` 的折中可用 `-o 2 --zc 12`；如果原本使用 Node `-o 5`，优先尝试 `-o 5 --fast`。追求速度且能接受约 2% 的 Rust `-o 2` 体积差距，可试 `-o 1 --zc 11`。这些参数仍无法达到 Rust 的压缩耗时。

## 额外九张 PNG/APNG 验证

使用生成的渐变、透明形状、plasma（文件名为 `photo.png`，并非真实照片），以及索引色、透明色、16 位、交错 16 位、小文件和 APNG。每个组合一次预热、三次测量；耗时为同步 API 中位数之和。

| 参数组合 | 总体积 B | API 耗时 s |
| --- | ---: | ---: |
| 原 `-o 2` | 533,909 | 3.190 |
| 原 `-o 5` | 514,414 | 23.488 |
| `-o 1 --zc 11` | 588,102 | 2.755 |
| `-o 2 --zc 12` | 514,182 | 4.819 |
| `-o 5 --fast` | 514,174 | 7.055 |
| 深度 32，三轮解析 | 544,425 | 2.781 |

八张静态 PNG 的 `-o 5 --fast` 与原 `-o 5` 输出 SHA-256 一致；APNG 从 62,134 B 降至 61,894 B。选出的首帧滤镜也用于后续帧，因此首帧试压缩更多不保证整个 APNG 更小。该组合在这九张图上减少约 70% 的 API 耗时，且没有体积退步。

`-o 2 --zc 12` 在九张图上均不大于原 `-o 2`；但删减滤镜的总字节增加约 10.2%，搜索深度减到 32 的总字节增加约 2.0%。逐图退步尤其明显：渐变从 24,141 B 增至 32,684 B（+35.39%），透明形状从 3,966 B 增至 4,350 B（+9.68%）。因此不建议将更浅搜索或更少滤镜直接设为通用默认值。

全部七档 CLI、四图调参、参数 CLI 复测、额外九图调参均完成。所有测量输出通过独立像素／动画帧验证及确定性检查，公开参数组合的 API 与 CLI 输出也逐字节一致。

```sh
npm run build:ts
node benchmark/presets.mjs --runs 3 --output benchmark/presets.json
node benchmark/tune.mjs --output benchmark/tuning-screen.json
node benchmark/tune.mjs --corpus sample --runs 3 --warmup 1 \
  --candidates baseline-o2,two-filters-z11,four-filters-z10,four-filters-z12,o5-fast,depth32-passes3,depth64-passes2 \
  --output benchmark/tuning-results.json
node benchmark/presets.mjs --runs 3 \
  --profiles baseline-o2,two-filters-z11,four-filters-z12,o5-fast \
  --output benchmark/tuned-cli.json
node benchmark/tune.mjs --corpus validation --runs 3 --warmup 1 \
  --candidates baseline-o2,baseline-o5,two-filters-z11,four-filters-z12,o5-fast,depth32-passes3 \
  --output benchmark/tuning-validation.json
```

`tune.mjs` 为各候选构建相同配置的临时 API bundle，通过构建插件修改实验性搜索深度／解析轮数，不修改源码文件。`presets.mjs` 可通过 `--profiles` 复测公开 CLI 参数组合；原始 CLI 报告 `REPORT.md` 和 `results.json` 不会被覆盖。
