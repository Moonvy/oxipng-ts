# 第四轮优化试验

日期：2026-10-11（Asia/Shanghai）。基线为第三轮最终代码（`d8c0f23` 的压缩实现），构建保存于本地 `benchmark/baseline-round4/dist/`。

## 试验计划

1. 对当前版本的 Qjiao 预设 6 重新采样，确认第三轮后热点占比。
2. GPT-6.1 sol 子 Agent 尝试候选前缀缓存和长匹配批量比较，保持匹配候选顺序、搜索量、lazy、窗口和块边界完全一致。
3. GPT-6.1 sol 子 Agent 尝试合并 MinSum 过滤生成和评分，避免重复扫描；过滤选择、并列排序、透明像素处理和 interlace 结果保持一致。
4. 按方案单独验证和测量，无收益或有回退的实现撤回。必要时再尝试减少 token 频率统计的重复遍历。
5. 最终执行类型检查、完整测试、DEFLATE 全等级字节对照和独立解压，再在前台浏览器主线程比较第三轮基线与本轮结果。继续禁用 Worker、SharedWorker、WebAssembly。

## 结果

完成。相对第三轮最终版本，前台 Chrome 四张图的中位耗时之和：预设 0 减少 **10.3%**，默认预设 2 减少 **4.1%**，预设 6 减少 **5.3%**。12 组中位数全部改善，全部 96 次输出验证通过。

基线 Qjiao 预设 6 的 Node CPU 采样用时 11.235 秒；`findMatch` 占采样 88.3%，`deflateInto` 5.0%，`filterLine` 1.6%，`filterImage` 1.0%，`emitBlock` 0.7%。这是定位热点的辅助结果，最终速度结论使用前台浏览器主线程计时。

首轮候选前缀缓存实验没有收益：保留候选顺序、仅替代候选 DataView 读取的版本，在四张图的前 100 万字节过滤数据、等级 8/12 的 8 组微测中慢约 2–12%；前置前缀拒绝版本慢约 8–29%。各版本输出逐字节一致且通过独立 zlib 解压，但均不保留。长匹配比较另外独立测试，避免缓存的负面影响掩盖其他方案。

## 保留的实现

- 匹配搜索的四字节比较：对两个 little-endian 词做 XOR，用 `clz32(diff & -diff)` 定位首个不同字节，省去重新逐字节寻找差异的位置。不增加缓存，不改搜索深度、候选顺序、lazy 和匹配长度。
- MinSum 过滤评分：在生成过滤字节时累计有符号绝对值；累积分数不小于最佳分数时提前结束本次候选。仍将过滤器字节计入分数，保留严格小于的并列规则；透明像素优化在评分前完整执行，保留后续候选依赖的顺序突变。

16 字节展开大多慢约 0.6–3.2%；token 频率融合约在 ±1.5% 内浮动，没有稳定收益，均不保留。

## 辅助微测

匹配搜索使用四张实际 PNG 解压后的原始过滤数据，截取前 100 万字节，分别测等级 8/12。方案消融和 XOR 独立复测均逐字节对照并通过 zlib 解压。复测每组 5 轮交替计时，8 组中位数均减少约 2.3–5.8%。原始记录：

- [缓存试验](comparison-round4-encoder-cache.jsonl)
- [独立消融](comparison-round4-encoder-ablations.jsonl)
- [XOR 复测](comparison-round4-encoder-xor-retest.jsonl)

MinSum 使用 512×128 的随机、渐变、结构化和透明数据，单独测 `filterImage`。充分预热后随机数据加速 1.34–1.37 倍，透明 RGBA 1.32 倍，结构化及渐变 2.55–3.10 倍。首轮存在 JIT 分层影响，保留原始记录但结论只采用充分预热后的复测。[原始时间、输入生成方法与预热过程](comparison-round4-minsum.json)。这些均是 Node 辅助微测，不代表整次 PNG 压缩或浏览器收益。

## 正确性验证

- 构建和 TypeScript 检查通过；14 个测试文件、477 项测试全部通过。
- DEFLATE 等级 0–12 的 390 组 raw/zlib 流与第三轮基线逐字节一致，独立 zlib 解压通过，覆盖窗口、块边界及 offset 输入。
- 新增匹配测试覆盖各字节位置、bit 31、尾部、窗口和块边界，共 201 条基线流指纹，并验证精确 size limit。
- 新增 MinSum 测试覆盖 504 个格式/位深/交错/alpha 组合，过滤字节、选择顺序与基线一致，输入 backing buffer 不变；另验证有符号评分、并列和提前结束时的 alpha 更新。
- ESM/CJS 公共导出集合不变，CJS 和 ESM 的压缩输出一致。
- 两位子 Agent 交叉静态审阅通过，确认 XOR 首差异定位（含 bit 31）、读取边界及 MinSum 提前结束/alpha 顺序处理与旧实现等价。

## 代价与范围

未压缩 ESM bundle 从 142,643 增至 146,186 字节，增加 3,543 字节，主要来自 MinSum 专用循环。不增加匹配缓存或额外行工作区。压缩参数、过滤集合及 API 保持一致，代码修改由 GPT-6.1 sol 子 Agent 执行。

整次压缩收益来自四张现有图片和一个 Chrome/Apple M1 环境，不代表其他浏览器、设备或图片都能得到同样百分比。MinSum 微测的倍数只适用于过滤阶段，不能当作整次压缩倍数。Canvas 比较的是浏览器渲染后的 8-bit RGBA，带有浏览器颜色管理与 alpha 预乘行为；逐字节对照另外确保编码结果未改变。
