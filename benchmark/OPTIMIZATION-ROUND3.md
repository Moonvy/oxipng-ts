# 第三轮：Web 主线程性能优化

实施日期：2026-10-10；浏览器验收日期：2026-10-11（Asia/Shanghai）。基线提交：`71e2a48d58eed527ee629d7bdf94b0ae648590c0`，构建快照保存在本地 `benchmark/baseline-round3/dist/`。

## 计划与验收

1. 保存当前构建，检查真实图片预设 6 的 CPU 热点。以现有压缩参数和搜索顺序为约束，不通过减少候选、降低压缩等级或缩短搜索链换取速度。
2. 由 GPT-6.1 sol 子 Agent 优化候选评估：非最终轮复用精确 DEFLATE 计数，省去丢弃输出的位写入、输出缓冲和 Adler32；保留 zlib 开销、尺寸上限、排序与胜出数据缓存。
3. 由 GPT-6.1 sol 子 Agent 优化 Huffman 构树、位写入和匹配哈希的实现，保持 tie-break 和输出字节一致。只有有测量支持的改动才保留。
4. 将演示页面改为浏览器主线程执行，删除 Worker 路径；构建产物不依赖 Node API、WebWorker 或 Wasm。
5. 运行类型检查、完整测试、所有 DEFLATE 等级的基线字节对比和独立解压；在真实浏览器主线程对四张图片的预设 2、6 交替测量基线与新版，预热一次、三次测量取中位数，并验证完整输出相同和浏览器解码像素一致。

压缩效果采用比大小不回退更严格的验收：无时间截止条件下，验证用例输出必须与基线逐字节一致。用户设置时间上限时，更快的实现可能在期限内完成更多候选，不能保证选择结果相同。

## 保留的实现

- 非最终轮候选评估直接复用编码器的精确尺寸计数，加上 6 字节 zlib 包装。省去这些试验的输出缓冲、逐 token 写入、编码表及 Adler32；最终轮仍生成真实数据。候选尺寸上限、排序、过滤缓存、trace 和 deadline 检查保持原有逻辑。
- Huffman 合并节点时执行一次 pop 和一次 root replacement，使用 hole sift 减少堆数组写入；利用父节点编号大于子节点的性质逆序传播深度，避免每个叶节点重复回溯。频率相同的节点继续按原编号排序。
- 位写入器使用整数移位处理低 32 位，单独保留跨越 32 位时的高位，覆盖最多 35 位的累积值；保留原有尺寸上限和字节对齐行为。
- 匹配搜索使用局部 DataView、缓存最佳匹配末尾的拒绝检查字节；批量插入哈希使用同一四字节小端读取。窗口、链深、lazy 选择、哈希值和候选访问次序不变。
- 演示页面移除 Worker 文件和调用路径，主线程压缩前让出一次事件循环显示状态；正确传播异常，并直接用返回的 Uint8Array 构造 Blob，保留其有效字节范围。请求序号避免异步读文件/加载样本覆盖后来请求。

子 Agent 的 Node/V8 微基准用于筛选方案：Huffman 约减少 30.6% 耗时，位写入约减少 1.4%；Qjiao 原始过滤数据前 100 万字节的编码等级 2/8 分别约减少 9.6%/6.1%。这些是局部实验，不代表完整 PNG 或浏览器性能。展开位写入循环的试验略有退化，已撤回。

## 验证与浏览器结果

完整构建、类型检查及 12 个文件中的 458 项测试全部通过。390 组 raw/zlib 流与基线逐字节一致，并通过 Node zlib 独立解压；ESM/CJS 公共导出集合保持一致，CJS 编码输出也与基线一致。

新增的 20 项测试覆盖精确 zlib 尺寸和上限、候选并列排序、过滤缓存、deadline、独立 Huffman 排序队列对照、所有 pending-bit/count 组合（包括 33–35 位累计值）、随机位写入、字节对齐及拒绝写入后的状态。演示页面在浏览器中通过正常 Shapes 样本和无效 PNG 的错误显示检查。

浏览器基准的运行和基线重建方法见 [BROWSER-ROUND3.md](./BROWSER-ROUND3.md)。压缩在浏览器 window 主线程执行；Node 只提供本地静态文件和保存 JSON。计时包括完整优化流程，输入复制、参数创建和像素检查在计时区间之外。每次调用均检查输出字节、输入不变性和浏览器独立解码后的 Canvas 像素；Worker、SharedWorker、WebAssembly 在模块加载前禁用。

测量环境修正：早期尝试中，自动化读取测试标签页并不等于浏览器实际选中了该标签页。原生 Chrome 界面确认另一页处于选中状态，测试受到后台调度与 requestAnimationFrame 暂停影响，耗时波动数倍；这些未完成的测量不用于性能结论。最终运行通过原生界面选中测试标签页，启动延迟 5 秒让操作结束，并在启动、每次压缩前后、完成时校验 `document.visibilityState`，监视所有可见性变化；进入后台即整轮失败。计时期间只读取服务器保存的进度文件，不读取浏览器 DOM/AX 或运行其他性能任务。
