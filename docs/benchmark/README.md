# Benchmark

Compares Rust oxipng and Node with available Porffor and static LLVM ScriptC builds on the four PNGs in
`sample/`. All receive the same options; Node/Porffor/ScriptC must produce identical
bytes or the benchmark fails.

## Run

Install Rust oxipng (`brew install oxipng` on macOS) and follow the
[native build prerequisites](../README.md#native-cli). Then:

```sh
npm run build:ts
npm run build:bin -- porffor scriptc
npm run benchmark                            # -o 2, three runs, no warmup
npm run benchmark:min                        # Rust + Node only, three runs, no warmup
npm run benchmark -- --opt 6 --runs 3
```

`benchmark:min` compares only Rust Native and the Node.js TypeScript build.
Each image and engine is measured three times without warmup; the fastest time
is discarded and the other two are averaged. `--runs` can increase the number
of measurements but must be at least three. `--warmup` accepts only `0`.
Run `npm run build:ts` after source changes. It writes the same `REPORT.md` and
`results.json` as the full benchmark; use `--output-dir` to keep a separate report.

Build outputs are independent: `build:ts` clears `dist/js`, `build:bin` clears
`dist/bin`, and `build:site` clears `docs`. The benchmark automatically includes
available Porffor and ScriptC executables from `dist/bin`; absent targets
are omitted. Explicit binary overrides must exist and run successfully.
`build:bin` defaults to targets with installed compilers and skips missing ones;
explicitly selected targets must have their compiler installed.

## Binary paths

| Implementation | Override | Default |
| --- | --- | --- |
| Rust | `OXIPNG_BIN` | `dist/bin/oxipng`, PATH, `~/.local/bin/oxipng`, local build, system locations |
| Porffor | `OXIPNG_TS_PORFFOR_BIN` | `dist/bin/oxipng-ts-porffor` |
| ScriptC | `OXIPNG_TS_SCRIPTC_BIN` | `dist/bin/oxipng-ts-scriptc` |

`PORFFOR_BIN` selects the Porffor **compiler**, not its output executable.
The ScriptC binary's adjacent `.build.json` identifies compiler version and mode;
external binaries without metadata are reported as unknown mode.

## Measurements

Every file run starts a fresh process and includes startup. For each image and
engine, the benchmark discards the fastest of three measured times and averages
the other two; there is no warmup. With a custom `--runs` value, it discards the
fastest time and averages the rest. Startup is measured separately by compressing
the 1×1 PNG at `test/files/fully_optimized.png` in three fresh processes; the
fastest result is reported, with no warmup.
The all-images comparison sums each engine's per-image times and compares those
totals, so longer-running images contribute more to the result.
Byte parity checks run outside the timed region.

Console output shows discovery, startup timing, the current image and engine,
measured round counts, completed rounds, elapsed time, byte checks and
report generation. Terminals update the active line every second; redirected
logs print a heartbeat every 15 seconds. Long-running rounds remain visible
without an estimated completion time. Ctrl+C stops the active child process,
cleans temporary outputs and leaves previous reports intact. The final console
table includes total output size, elapsed CLI time, startup and ratios to Node.

Rust uses its default thread count and libdeflate. The available TypeScript builds use
the same built-in encoder on one thread, so Rust output size and timing can differ.
The default ScriptC target requires 100% static coverage and includes no JS engine.

Results are written to [REPORT.md](REPORT.md) and [results.json](results.json).
The checked-in reports describe their recorded run; rerun the benchmark to update
measurements.

Use `--output-dir /existing/directory` to write reports elsewhere.
The local two-way results from before the pull are preserved in
[pre-pull-REPORT.md](pre-pull-REPORT.md) and
[pre-pull-results.json](pre-pull-results.json); they describe the earlier build.

## UPNG.js comparison

The separate comparison measures oxipng-ts presets `-o 0` through `-o 3`
against lossless UPNG.js:

```sh
npm run build:ts
npm run benchmark:upng -- --runs 5
```

UPNG.js uses `UPNG.encode(..., cnum=0)`, always re-encodes, and drops source
metadata. This comparison supports still PNGs with at most 8-bit channels;
animated and 16-bit PNGs fail explicitly. Both encoders' decoded pixels are
checked outside the timed interval. Timings include Node process startup.

Reports are written to [UPNG-REPORT.md](UPNG-REPORT.md) and
[upng-results.json](upng-results.json). The command accepts `--runs`,
`--warmup`, and `--output-dir`; saved results describe the build at measurement
time and are not regenerated by pulling code.

## In-process before/after measurements

`npm run benchmark:core` measures the public synchronous API without process
startup. It reports median and minimum elapsed times, checks independently decoded
pixels using pngjs at full 16-bit precision, checks every APNG frame and its control
fields, and checks deterministic output outside the timed region.
With `--baseline`, baseline/current runs alternate their order to reduce warmup
and ordering bias. The default is five measured runs and two warmups per file.

To reproduce the baseline used for this optimization, export revision
`65775627960607f97d3251d6926ec8c10244c2da` and bundle its library with esbuild:

```sh
baseline_dir=$(mktemp -d)
git archive 65775627960607f97d3251d6926ec8c10244c2da | tar -x -C "$baseline_dir"
node_modules/.bin/esbuild "$baseline_dir/src/index.ts" --bundle --platform=node \
  --format=esm --outfile="$baseline_dir/index.mjs"
npm run build:ts
npm run benchmark:core -- --baseline "$baseline_dir/index.mjs" --opt 2
```

Use `--opt 6` for maximum compression and `--output /path/results.json` to keep
separate runs. Results default to [core-results.json](core-results.json).
The CLI benchmark above remains the Rust comparison; it includes process
startup and uses Rust's default thread count. See [PERFORMANCE.md](PERFORMANCE.md).

`--corpus extended` adds generated gradients, transparent shapes and plasma,
plus indexed, transparent, 16-bit, interlaced, small PNG and APNG fixtures: 13
files in total. The generated `photo.png` is plasma, not a real photograph.
Run `npm run build:ts` and `npm run build:site` first to generate the three
demo samples in `docs/samples`. `--rust /path/to/oxipng`
adds an independently validated Rust **size** reference; it does not mix CLI
timing with synchronous API timing.

To reproduce the baseline immediately before adaptive parsing/block splitting,
apply [adaptive-baseline.patch](adaptive-baseline.patch) to the original revision:

```sh
baseline_dir=$(mktemp -d)
git archive 65775627960607f97d3251d6926ec8c10244c2da | tar -x -C "$baseline_dir"
patch -d "$baseline_dir" -p1 < benchmark/adaptive-baseline.patch
node_modules/.bin/esbuild "$baseline_dir/src/index.ts" --bundle --platform=node \
  --format=esm --outfile="$baseline_dir/index.mjs"
npm run build:ts
npm run benchmark:core -- --baseline "$baseline_dir/index.mjs" --corpus extended \
  --rust "$HOME/.local/bin/oxipng" --opt 2 --runs 3 --warmup 1 \
  --output benchmark/adaptive-results.json
```

Repeat with `--opt 4 --output benchmark/adaptive-level4-results.json` for the
higher preset. Results retain every measured sample; per-file regressions should
be considered alongside totals.

## Match-alternative compression measurements

The latest ratio optimization replaces the high-level match finder and cost
model. It reduces output size while increasing compression time; see
[PERFORMANCE.md](PERFORMANCE.md#latest-phase-preserving-match-alternatives).
Reproduce against the immediately preceding revision:

```sh
baseline_dir=$(mktemp -d)
git archive d32ce7dde7bd95c1f7adbd7a0fbffd386dea28b0 | tar -x -C "$baseline_dir"
node_modules/.bin/esbuild "$baseline_dir/src/index.ts" --bundle --platform=node \
  --format=esm --outfile="$baseline_dir/index.mjs"
npm run build
npm run benchmark:core -- --baseline "$baseline_dir/index.mjs" --corpus extended \
  --rust "$HOME/.local/bin/oxipng" --opt 2 --runs 3 --warmup 1 \
  --output benchmark/match-cache-results.json
npm run benchmark:core -- --baseline "$baseline_dir/index.mjs" --corpus extended \
  --rust "$HOME/.local/bin/oxipng" --opt 4 --runs 3 --warmup 1 \
  --output benchmark/match-cache-level4-results.json
```

The baseline encoder's SHA-256 is
`a198f9461d469674699879b416bc87c713e90d01bb6e9b09bdf0fd8c0c080a8f`.
These API measurements exclude startup and validate full-precision pixels,
APNG frames and controls, and deterministic output independently of timing.

## Presets and speed/size tuning

See [PRESETS.md](PRESETS.md) for the complete Rust/Node `-o 0–6` CLI matrix,
filter/compression/depth/pass experiments, and additional PNG/APNG validation.
The subsequent default `-o 2` budget change, including the seven-file sample
corpus and broader fixture checks, is recorded in [DEFAULT-O2.md](DEFAULT-O2.md).

The current match-interior insertion budget, its per-image 2% size check,
five-run API comparison and fresh-process CLI measurements are recorded in
[O2-INSERTION.md](O2-INSERTION.md). Use `--node-cli PATH` with `benchmark/run.mjs`
to compare a saved CLI build, and `--output-dir` to preserve existing reports.
These scripts write separate artifacts and preserve the main CLI report:

```sh
npm run build:ts
node benchmark/presets.mjs --runs 3 --output benchmark/presets.json
node benchmark/tune.mjs --output benchmark/tuning-screen.json
```

`presets.mjs` also accepts `--profiles` with named public CLI combinations;
`tune.mjs` accepts `--candidates`, `--runs`, `--warmup`, and
`--corpus pilot|sample|extended|validation|fixtures`. `validation` contains only the nine
additional generated/fixture files; `fixtures` audits 8-bit fixtures with at
least 64 KiB of raw pixels and records invalid input skips. Experimental encoder parameters are applied
to temporary bundles, without changing production defaults. Both scripts check
decoded pixels and deterministic output outside measured intervals.
